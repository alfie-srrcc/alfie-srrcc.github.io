01 / Map generation

A different layout from the same rules

The map begins as a two-dimensional list of walkable cells. Alternate rows become walls, then randomly selected cells in the internal wall rows reopen as passages. Powerups and keys are placed on available cells in even-numbered rows.

Small, medium and large maps use 10 × 10, 15 × 15 and 20 × 20 cells. The window stays 800 × 600 pixels, so cell dimensions adjust with the map size.

The illustration shows the small-map pattern. Random openings can repeat; the generator does not currently guarantee a perfect maze.

02 / Movement & collision

Check the next position before moving

WASD input chooses a direction. The player is represented by a rectangle, and a second rectangle predicts its next position. If that rectangle overlaps a wall, the move is cancelled. Otherwise, the player's coordinates and rectangle advance together.

This separates input, collision checks and drawing into distinct steps. The prototype moves in pixel increments rather than jumping a whole grid square.

Next position is clear → movement allowed.

03 / Keys & inventory

Turn a collision into a collected item

Yellow cells represent keys. When the player overlaps one, its map value changes from 3 to 1, turning it back into a path. Its collision entry is removed, and a key is pushed into the player's fixed-capacity inventory.

The key stack stores items in a list and advances a front index on each push. Its size method counts collected keys. The current small-map entry point creates 15 keys.

The win-check method exists, but an exit and completed victory flow are not wired into this repository version.

04 / Adaptive powerups

Use performance to choose a reward tier

Purple cells represent powerups. Collecting one selects a low, medium or high tier using the player's ability score, then randomly chooses one of two labels in that tier. The item is added to a separate powerup stack.

Ability is calculated as keys collected ÷ elapsed seconds. The thresholds vary by map size. For a small map, a score of at least 0.10 selects high; a score above 0.05 and below 0.10 selects medium; lower scores select low.

The current code selects and stores reward labels. Individual powerup effects are not implemented yet. At exactly 0.05, the small-map rule selects low.

One update, connected systems

Input → predict → collect → calculate → redraw

A movement request runs through the collision system. Item checks update the map and inventories, the ability score is recalculated, and the map and player are drawn again. Classes for the game, map, player and stacks keep these responsibilities separate.

These diagrams explain the Python mechanics. They are not a playable game. The A* study above represents separate pathfinding work shared during development; it is not connected to the current main-branch game loop.

The maths behind this method

RSA encryption uses Bob’s public key; only his private key can decrypt. Diffie–Hellman lets both parties derive a shared secret without transmitting that secret.

What this demonstrates

Encryption, key agreement and integrity

Educational simulation, not a secure chat service. Both participants run in one browser, private key material exists in local memory, and nothing is sent to another person. It does not verify who Alice or Bob really is. Use sample messages. Keys disappear on reset or reload.

Inside the project

Small pieces.
Connected thinking.

01 / REPRESENT

From grid to graph

Represent walkable map squares as nodes with coordinates. Connect neighbouring nodes through weighted edges so the map can be searched.

02 / SEARCH

Find the next step

A* combines the distance travelled with an estimate of the distance remaining. A Manhattan-distance heuristic guides the search across the grid.

03 / RECONSTRUCT

Trace the route

Track each node's predecessor, then follow the chain backwards from the target. Reverse the result to produce a path from start to finish.

# Estimate distance on a four-directional grid
def heuristic(node, target):
    return abs(node.x - target.x) + abs(node.y - target.y)
